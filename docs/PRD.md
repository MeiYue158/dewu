# PRD｜多品类智能对话导购（得物场景）

## 1. 背景与目标

电商用户从搜索或详情页进入咨询后，问题会从“帮我选”延伸到规格、兼容、服务和比较，并在追问中改变。项目要做一个可运行、可解释、可评测的教学应用，覆盖鞋履、服饰、数码三类。

**产品目标**：在带来源的数据范围内，将模糊需求转化为结构化约束，完成澄清、召回、硬过滤、可解释排序和比较，并在缺失、过期、冲突或异常时明确回退。

**不做**：得物官方系统接入、实时库存/价格承诺、支付下单、图像检索、价格预测、模型训练或微调。

## 2. 用户与场景

- 访客：从品类入口或商品详情开始咨询。
- 选购者：有预算、用途、尺码/规格、兼容条件，希望得到候选和取舍解释。
- 学习者岳美：需要能独立启动、修改数据、运行测试并解释设计。

首要任务：礼物选购、鞋履比较、服饰属性咨询、数码兼容咨询、多轮修改预算/用途、无匹配与无法核实处理。

## 3. 用户故事与需求

| ID | 用户故事 | 验收标准 |
|---|---|---|
| FR-01 | 我可以选择鞋履/服饰/数码后开始会话 | 三类入口进入统一会话，保存当前品类 |
| FR-02 | 我可以用自然语言表达模糊需求 | 系统抽取已识别意图/约束，并对缺失关键条件追问 |
| FR-03 | 我可以修改预算、用途、尺码或设备 | 新约束覆盖旧值，响应中说明候选变化原因 |
| FR-04 | 我可以查看商品候选 | 候选含名称、SKU/规格、价格（若有）、匹配点、来源、更新时间 |
| FR-05 | 我可以比较商品 | 同品类至少两项逐字段对比；缺失字段显示无法核实 |
| FR-06 | 我可以追问规格/服务 | 只引用对应工具返回的事实；来源不足时拒答并给下一步 |
| FR-07 | 我可以处理无匹配和异常 | 给出冲突条件、放宽建议、重试或重新提问 |
| FR-08 | 我可以看到运行状态 | 加载、部分返回、超时、重试、会话重置均可操作 |
| FR-09 | 教师可以复现评测 | 一条命令运行跨品类任务，输出逐案例结果和失败分类 |

## 4. 数据与事实规则

每条正式商品/规格记录至少包括 `product_id`、`category`、品类属性、来源、`facts_updated_at`；SKU 级筛选必须使用 `sku_id`、价格、可售状态（若来源提供）。公开商品快照的展示价不当作实时 SKU 价格；品牌参考资料未完成 SPU 对应时不得自动合并；虚构目录只能进入测试模式。

事实规则：模型不能补猜库存、材质、折扣、售后或兼容性；缺失、过期、冲突信息输出“无法核实”，同时保留可核查来源和时间。

## 5. 指标

### 离线指标（首版必须）

- 任务完成率：案例是否达到目标状态（候选/比较/明确无法核实）。
- 硬条件满足率：预算、尺码、可售、兼容等硬条件均满足的候选比例。
- 事实依据正确率：结论是否能回指当前数据字段和来源。
- 澄清有效率：每轮追问是否减少关键缺失槽位或解决冲突。
- 卡片动作成功率：详情、比较、换一件、重试事件是否正确处理。
- 响应时间：记录端到端和工具耗时分位数。

真实点击、转化、GMV 等业务指标只有接入真实线上埋点后才能报告。

## 6. 非功能需求

- 可运行：本地一条命令启动前后端，README 给出环境变量和测试命令。
- 可解释：每个推荐理由和事实字段都能追溯来源/更新时间。
- 可恢复：工具超时、模型错误、数据缺失不丢会话状态。
- 安全：密钥只从环境变量读取；日志脱敏；不记录完整敏感输入。
- 可测试：核心状态、过滤排序、事实边界和事件协议有自动化测试。

## 7. 范围优先级

P0：会话、澄清、三类查询、硬过滤、商品/对比卡、来源与无法核实、异常恢复、离线评测。

P1：流式文本、会话历史、策略版本对比、评测可视化。

P2：真实详情跳转、更多品类、人工客服转接。具体接入前需重新确认数据与合规条件。

## 8. 端到端验收

岳美在空环境启动项目，完成一条模糊需求到候选、一次预算修改、一次同品类比较、一次缺失事实回退、一次工具超时重试；随后修改一条商品资料并重新运行评测，系统行为和报告可复现。验收时明确项目是独立教学实现，不表述为得物内部成果。

## 9. 已确认决策（2026-10-20）

- 前后端分离：前端 React + TypeScript + Ant Design，后端 Python + FastAPI，分别启动与构建。
- 后端为项目核心：负责会话状态、需求理解、工具编排、事实核查、检索过滤、排序比较和评测；前端负责展示与交互。
- 界面移动优先，同时适配桌面；使用 Ant Design 组件，窄屏采用单列和抽屉布局。
- 模型采用可配置的 OpenAI 兼容接口；先完成非流式完整回复，流式作为 P1。
- 会话使用 SQLite 持久化，支持服务重启后恢复；历史会话管理界面作为 P1。
- 数据先采用三品类的小规模可核对样本，手动导入更新，保留字段级来源和时间。
- P0 提供项目内商品详情页；已核实的外部来源链接可展示，外链覆盖率不作为首版验收门槛。
